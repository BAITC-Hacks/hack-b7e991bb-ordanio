# Прогноз выработки ВЭС: агент на архивных прогнозах погоды

Команда Ordanio, HackAlem AI, Астана, 23.09.2026. Задача «Agentic AI для прогнозирования выработки ВЭС»
(владелец задачи: Самрук-Казына), трек «Энергетика».

Развёрнутая версия: https://hackathon.ordanio.com (та же версия, что в репозитории, Docker на сервере
в Амстердаме, с ключом OpenAI: работают и прогнозы, и сводки от модели, и чат с агентом).

## Назначение

Ветростанция должна каждый день заранее сообщать, сколько энергии дадут её турбины завтра
и послезавтра по часам: ошибка прогноза стоит денег на балансирующем рынке. Проект отвечает
на вопрос «сколько выдадут две турбины в каждый из следующих 48 часов», если сегодня известен
только прогноз погоды, и делает это сам, каждый день, для каждого дня тестового периода
с 31 января по 28 февраля 2026.

Вход: история работы двух турбин (10-минутные замеры с 11.03.2023 по 31.01.2026, выданы
организаторами, `data/raw/`) и архивные прогнозы погоды Open-Meteo по координатам турбин.
Выход: для каждого дня выпуска почасовой прогноз на 48 часов по каждой турбине с коридором
неопределённости (p10, p50, p90), журнал агента с анализом дня, файлы CSV.

## Что реализовано

- Модель прогнозирования по историческим данным турбин: три квантильные модели градиентного
  бустинга (scikit-learn), обученные на парах «прогноз погоды на этот час → фактическая выработка».
  Признаки только из прогноза погоды и календаря, замеры турбины в признаки не входят.
- Самостоятельное получение прогнозов погоды по координатам турбин из открытого источника
  Open-Meteo (без ключа и регистрации), с кэшем ответов в репозитории.
- Почасовой прогноз на 48 часов по двум турбинам с коридором p10–p90.
- Agentic-цикл на каждый день выпуска: погода, известная в этот день → признаки → модель → CSV →
  анализ (сравнение с прогнозом предыдущего дня, часы низкой уверенности, экстремальный ветер,
  ошибка за вчера при наличии факта) → сводка в журнал → следующий день с пересчётом.
- Воспроизведение «как в прошлом» на 31.01–28.02.2026 одной командой: 29 прогнозов и общий журнал.
- Проверка модели на январе 2026, который в обучение не входил, ровно тем способом, каким агент
  работает в феврале, против двух точек отсчёта; отчёт с числами `model/artifacts/report.md`.
- Веб-страница: выбор даты, кнопка, журнал шагов, графики с коридором, таблица, CSV, прогон
  всего февраля, панель проверки на январе, вопросы агенту (при наличии ключа OpenAI).
- LLM-аналитик (OpenAI, опционально): сводка дня по числам анализа и ответы на вопросы через
  инструменты (прогноз на дату, погода, сравнение запусков, метрики проверки). Модельная сводка
  строится для одного дня (кнопка или `--date`), при прогоне всего периода сводки шаблонные,
  чтобы прогон занимал секунды. Без ключа цикл и страница работают полностью, сводка собирается
  по шаблону, чат отключён с надписью.
- Тест сценария `pytest`, печатает PASS. Docker-запуск одной командой.

## Основной сценарий

1. Пользователь выбирает дату выпуска D (31.01.2026 … 28.02.2026) и нажимает «Сформировать прогноз».
2. Агент получает из Open-Meteo прогноз погоды, известный в день D, на часы D+1 00:00 … D+2 23:00:
   для D+1 прогноз суточной давности (`previous_day1`), для D+2 двухсуточной (`previous_day2`).
3. Агент собирает признаки и запускает модель.
4. Агент записывает 96 строк (48 часов × 2 турбины) в `output/forecasts/forecast_<D>.csv`.
5. Агент анализирует результат: суммарная энергия по суткам, изменения к прогнозу предыдущего дня
   на те же часы, часы низкой уверенности, часы с ветром выше 25 м/с (штатная остановка турбины),
   ошибка за вчера по факту, если факт есть (январь).
6. Агент пишет сводку дня в `output/journal.md` и `output/runs/<D>.json`, затем переходит к D+1.

## Архитектура

```
данные турбин (10 мин)  ──►  model/prepare  ──►  часовые ряды, фильтр простоев
Open-Meteo, архив и previous-runs ──►  model/weather (кэш data/weather_cache) ──►  model/features ──► model/train
                                                                                              │
                                                                                              ▼
день D ──► agent: погода на D ──► признаки ──► model/predict (p10/p50/p90) ──► CSV ──► анализ ──► журнал ──► D+1
                                                                                              │
web/app (FastAPI + одна страница) ◄───────────────────────────────────────────────────────────┘
```

- `common/config.py` — координаты, пути, период, часовой пояс.
- `data/raw/` — данные организаторов (источник в `data/raw/ИСТОЧНИК.md`); `data/weather_cache/` —
  ответы Open-Meteo, чтобы результат воспроизводился без сети.
- `model/` — подготовка данных, погода, признаки, обучение, предсказание; `model/artifacts/` —
  обученные модели, метрики, отчёт и таблица проверки.
- `agent/` — инструменты цикла, суточный запуск, прогон по периоду, LLM-аналитик.
- `web/` — API и одна HTML-страница без сборки и внешних библиотек (график в SVG).
- `tests/` — проверочный сценарий; `examples/` — примеры выходных файлов; `docs/` — контракт модулей,
  журнал экспериментов, текст ТЗ организаторов.

Что детерминировано, а что делает LLM. Погода, признаки, модель, файлы, правила анализа и журнал
по шаблону работают без ключа и без сети (из кэша); повторный прогон даёт байт в байт те же файлы.
Модель OpenAI используется только для человеческой сводки дня по числам анализа и для ответов
на вопросы через инструменты; она не может изменить прогноз.

Подробный контракт функций и колонок: `docs/architecture.md`.

## Как устроена модель и что показала проверка

Модель учится на прогнозе, а не на измеренном ветре: в день выпуска замеров за завтра ещё нет,
и модель, обученная на точном ветре, ошибается сильнее на прогнозном. Обучающая выборка:
архив свежих прогнозов с 2023 года плюс история прогнозов за сутки и за двое суток с марта 2024.
Один и тот же час факта входит в выборку до трёх раз с разными версиями прогноза (свежий, суточной
и двухсуточной давности), поэтому строк обучения 107 417 при 48 767 часах факта по двум турбинам;
январь 2026 в обучение не входил. 15 признаков: ветер на 10 и 100 м,
порывы, направление, температура, давление, час, месяц, турбина, давность прогноза, куб и сглаженный
ветер. Три модели `HistGradientBoostingRegressor(loss="quantile")` на квантили 0.1, 0.5, 0.9.

Проверка на январе 2026 повторяет работу агента: 31 дата выпуска, 2 914 часов с фактом.
Ошибки в долях номинальной мощности.

| Горизонт | Модель MAE | RMSE | Факт внутри p10–p90 | Кривая мощности MAE | Persistence MAE |
|---|---|---|---|---|---|
| Все 48 ч | 0.144 | 0.218 | 85.3 % | 0.158 | 0.365 |
| День 1 | 0.135 | 0.204 | 86.0 % | 0.149 | 0.386 |
| День 2 | 0.154 | 0.232 | 84.6 % | 0.168 | 0.343 |

Модель точнее кривой «ветер → мощность» во всех срезах и в 2.5 раза точнее правила «завтра как
сегодня». Коридор шире нужного: факт внутри в 85 % часов при цели 80 %. Что пробовали и что не помогло:
`docs/experiments.md`. Полный отчёт с фильтром данных, самопроверкой выравнивания по времени
и параметрами: `model/artifacts/report.md`.

## Технологии

Python 3.12, pandas, numpy, scikit-learn, httpx, joblib, FastAPI, uvicorn, python-dotenv, openai, pytest.
Одна HTML-страница без сборки. Docker. Источник погоды: Open-Meteo (Historical Forecast API
и Previous Runs API). LLM: OpenAI API, опционально.

## Установка

Установка возможна двумя способами.

Вариант A, Docker (установка и запуск одной командой, см. «Запуск»).

Вариант B, без Docker. Нужен Python 3.12. Команды даны для PowerShell и для bash, без `&&`.

PowerShell:
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

bash:
```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Ключ OpenAI не обязателен. Если он есть: скопировать `.env.example` в `.env` и вписать `OPENAI_API_KEY`.

## Запуск

Docker:
```
docker compose up --build
```

Без Docker (обученные модели лежат в репозитории, обучение повторять не нужно; при желании
`python -m model.train` переобучает их из кэша погоды за 1–2 минуты):
```
python -m web.app
```

Открыть http://localhost:8000. Выбрать дату, нажать «Сформировать прогноз».

Прогон всего периода из командной строки:
```
python -m agent.run --from 2026-01-31 --to 2026-02-28
```
Результат: `output/forecasts/forecast_2026-01-31.csv` … `forecast_2026-02-28.csv`, `output/journal.md`,
`output/runs/*.json`.

## Зависимости

Версии зафиксированы в `requirements.txt`. Внешний сервис один, Open-Meteo, открытые данные без
регистрации; кэш его ответов лежит в `data/weather_cache/`, при `WEATHER_OFFLINE=1` сеть не используется.
Обученные модели лежат в `model/artifacts/` и воспроизводятся командой `python -m model.train`
(детерминированно, `random_state=0`).

## Параметры окружения

`.env.example`:

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | ключ OpenAI для сводок дня и вопросов агенту; без него эти две функции отключены, остальное работает |
| `OPENAI_MODEL` | модель OpenAI для ответов на вопросы, по умолчанию `gpt-5.5` |
| `OPENAI_MODEL_NOTE` | модель для сводки дня, по умолчанию `gpt-5.4` (быстрее, 4–5 с на сводку) |
| `WEATHER_OFFLINE` | `1` запрещает обращения в сеть, погода только из кэша |

## Как проверить основной сценарий

1. Тест (обучение на срезе 90 дней во временную папку, прогон одного дня из кэша, проверка файла,
   кривой ввод):
```
pytest -q -s tests
```
Ожидаемый вывод заканчивается строкой `PASS` и `6 passed`.

2. Один день агента из командной строки:
```
python -m agent.run --date 2026-02-05
```
Ожидается файл `output/forecasts/forecast_2026-02-05.csv` на 96 строк (48 часов × 2 турбины)
с колонками `issue_date, target_time, lead_hours, turbine, ws100_forecast, temp_forecast, p10, p50, p90,
confidence, note`, значения p10 ≤ p50 ≤ p90 в пределах 0…1, и раздел «Выпуск 2026-02-05»
в `output/journal.md`. Пример такого файла и раздела: `examples/`.

3. Через API после `python -m web.app` или `docker compose up`:
```
curl -X POST "http://localhost:8000/api/run?issue_date=2026-02-05"
```
Ожидается JSON с полем `steps` (шесть шагов с временем) и 96 строками прогноза.

4. Кривой ввод: `python -m agent.run --date 2026-03-05` печатает, что дата вне периода
31.01–28.02.2026, код выхода 2; `curl -X POST "http://localhost:8000/api/run?issue_date=abc"`
отвечает 400 с текстом по-русски.

## Данные и внешние сервисы

Данные турбин выданы организаторами (`data/raw/ИСТОЧНИК.md`): шаг 10 минут, 11.03.2023–31.01.2026,
нормализованная мощность 0…1, замеренный ветер и температура. Погода: Open-Meteo, архив прогнозов
и предыдущие запуски по точке 43.6442, 78.5372 (турбины стоят в 240 м друг от друга, одна ячейка
погодной сетки). Открытые данные, лицензия CC BY 4.0. Кэш ответов в репозитории, 3,2 МБ.
LLM: OpenAI API по ключу пользователя, в него передаются только числа анализа дня и текст вопроса.

## Ограничения

Известные ограничения проекта, честно по факту:

- Фактической выработки за февраль 2026 в данных нет, поэтому качество показано на январе 2026;
  для февральских дней агент честно пишет «ошибка за вчера: нет факта».
- Открытый источник даёт прогнозы за сутки и за двое суток от начала дня; внутрисуточные обновления
  прогноза не используются, «повторный расчёт при обновлении» происходит раз в сутки.
- Часовой пояс данных принят как местное время; Казахстан перевёл часы на UTC+5 в марте 2024,
  самопроверка выравнивания (`model/artifacts/report.md`) показывает нулевой целый сдвиг в обоих
  периодах, но дробная часть часа не исправляется.
- Коридор p10–p90 шире нужного (факт внутри 85 % часов при цели 80 %).
- Координаты турбин взяты из ссылок в ТЗ; параметры турбин (высота ступицы, номинал) неизвестны,
  поэтому выработка нормирована так же, как в данных.
- Часы вероятного простоя (149) и неполные часы (120) исключены из обучения по простым правилам,
  ремонтные графики неизвестны.
- Сводка дня и чат работают только при ключе OpenAI; при ошибке API агент продолжает цикл.
