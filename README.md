# Прогноз выработки ВЭС: агент на архивных прогнозах погоды

Команда Ordanio, HackAlem AI, Астана, 23.09.2026. Задача «Agentic AI для прогнозирования выработки ВЭС»
(владелец задачи: Самрук-Казына), трек «Энергетика».

## Назначение

Ветростанция должна каждый день заранее сообщать, сколько энергии дадут её турбины завтра и послезавтра
по часам. Ошибка прогноза стоит денег на балансирующем рынке. Этот проект отвечает на вопрос
«сколько выдадут две турбины в каждый из следующих 48 часов», если сегодня известен только прогноз
погоды, и делает это сам, каждый день, для каждого дня тестового периода с 31 января по 28 февраля 2026.

Вход: история работы двух турбин (10-минутные замеры с марта 2023 по январь 2026, выданы организаторами)
и архивные прогнозы погоды из открытого источника Open-Meteo по координатам турбин.
Выход: для каждого дня выпуска почасовой прогноз на 48 часов по каждой турбине с коридором
неопределённости (нижняя, средняя, верхняя оценка), журнал агента с анализом дня и файлы CSV.

## Что реализовано

Раздел заполняется по ходу работы. Состояние на первый коммит: выбрана задача, описан сценарий,
спроектирована архитектура и контракт модулей (`docs/architecture.md`), разложены данные организаторов
и структура папок. Код в работе.

## Основной сценарий

1. Пользователь выбирает дату выпуска прогноза D (от 31.01.2026 до 28.02.2026) и нажимает «Сформировать прогноз».
2. Агент получает из Open-Meteo прогноз погоды, который был известен в день D, на часы D+1 00:00 … D+2 23:00.
3. Агент собирает признаки и запускает модель, обученную на истории турбин и архивных прогнозах.
4. Агент записывает 48 часовых значений по каждой турбине (p10, p50, p90) в `output/forecasts/forecast_<D>.csv`.
5. Агент анализирует результат: сравнивает с прогнозом предыдущего дня на те же часы, помечает часы
   низкой уверенности, считает суммарную энергию, при наличии факта за вчера считает ошибку.
6. Агент пишет сводку дня в `output/journal.md` и переходит к D+1, где всё пересчитывается на новых данных.

Тот же цикл запускается на весь период одной командой; результат — 29 файлов прогнозов и общий журнал.

## Архитектура

```
данные турбин (10 мин)  ──►  model/prepare  ──►  часовые ряды, фильтр простоев
Open-Meteo, архив прогнозов ──►  model/weather (кэш в data/weather_cache) ──►  model/features ──► model/train
                                                                                         │
                                                                                         ▼
день D ──► agent: погода на D ──► признаки ──► model/predict (p10/p50/p90) ──► CSV ──► анализ ──► журнал ──► D+1
                                                                                         │
web/app (FastAPI + одна страница) ◄──────────────────────────────────────────────────────┘
```

Части и их зоны (подробный контракт функций в `docs/architecture.md`):

- `data/` — исходные данные организаторов (`data/raw/`, источник описан в `data/raw/ИСТОЧНИК.md`)
  и кэш ответов Open-Meteo (`data/weather_cache/`), чтобы результат воспроизводился без сети.
- `model/` — подготовка данных, погода, признаки, обучение трёх моделей (квантили 0.1, 0.5, 0.9)
  и проверка на январе 2026, который в обучение не входит.
- `agent/` — суточный цикл с шагами-инструментами, анализ, журнал, прогон по периоду,
  LLM-аналитик и чат с инструментами (только при наличии ключа).
- `web/` — API и одна страница: выбор даты, кнопка, журнал шагов, график с коридором, таблица, CSV.
- `tests/` — проверочный сценарий, печатает PASS.
- `examples/` — примеры выходных файлов.

Что детерминировано, а что делает LLM. Получение погоды, признаки, модель, файлы, правила анализа
и журнал по шаблону работают без ключа и без сети (из кэша). Модель OpenAI используется только
для человеческой сводки дня и для ответов на вопросы по инструментам (прогноз, погода, сравнение
запусков). Без ключа эти две функции отключены с явной надписью, остальное работает.

## Технологии

Python 3.12, pandas, scikit-learn (HistGradientBoostingRegressor с квантильной функцией потерь),
httpx, FastAPI + uvicorn, одна HTML-страница без сборки и без внешних библиотек (график в SVG),
Docker. Источник погоды: Open-Meteo (Historical Forecast API и Previous Runs API), бесплатно, без ключа.
LLM: OpenAI API (опционально).

## Установка

Вариант A, Docker:

```
docker compose up --build
```

Вариант B, без Docker (команды даны для PowerShell и для bash отдельно, без `&&`):

PowerShell:
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

bash:
```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

```
python -m model.train
python -m web.app
```

Открыть http://localhost:8000. Прогон всего периода из командной строки:

```
python -m agent.run --from 2026-01-31 --to 2026-02-28
```

## Зависимости

Версии зафиксированы в `requirements.txt`. Внешний сервис один: Open-Meteo (открытые данные,
без регистрации). Кэш его ответов лежит в репозитории, при `WEATHER_OFFLINE=1` сеть не используется.

## Параметры окружения

См. `.env.example`. `OPENAI_API_KEY` нужен только для LLM-аналитика и чата; `WEATHER_OFFLINE=1`
запрещает обращения в сеть.

## Как проверить основной сценарий

Заполняется вместе с кодом: команда, входные данные, ожидаемый результат дословно, плюс `pytest -q`,
который печатает PASS.

## Соответствие требованиям задачи

| Требование ТЗ | Где в коде | Как проверить |
|---|---|---|
| Модель прогнозирования по историческим данным | `model/` | заполняется |
| Самостоятельное получение прогнозов погоды по координатам из открытого источника | `model/weather.py`, `agent/` | заполняется |
| Прогноз на 24–48 часов с почасовой детализацией | `agent/`, `output/forecasts/` | заполняется |
| Agentic-цикл: погода → подготовка → модель → прогноз → анализ → пересчёт | `agent/run.py` | заполняется |
| Воспроизведение «как в прошлом» на 31.01–28.02.2026 с архивными прогнозами | `agent/run.py --from --to` | заполняется |

## Данные и внешние сервисы

Данные турбин выданы организаторами (см. `data/raw/ИСТОЧНИК.md`). Фактический диапазон
11.03.2023–31.01.2026, февральских фактов нет, поэтому качество модели проверяется на январе 2026.
Погода: Open-Meteo, архив прогнозов и предыдущие запуски по точке 43.6442, 78.5372
(турбины стоят в 240 м друг от друга, это одна ячейка погодной сетки).

## Ограничения

Заполняется честно по факту. Уже известно: факта за февраль 2026 в данных нет; координаты турбин
взяты из ссылок ТЗ; часовой пояс данных принят как Asia/Almaty (с учётом перевода Казахстана
на UTC+5 в марте 2024), выравнивание по времени проверяется автоматически и отражается в отчёте модели.
